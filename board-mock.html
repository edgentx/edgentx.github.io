Design Principles Demonstrated

Icon-first, space-efficient

All actions use icon buttons with accessible labels. No long text labels clutter the surface. The rail uses icons for navigation with text labels alongside them. The toolbar is dense but touch-friendly: buttons are 36px minimum, with adequate spacing. Follows Ancora's operational UI patterns with the board's density requirements winning over Ancora's lighter patient-portal approach.

Skeleton loading states

The initial load shows skeleton rows with a subtle animation. No spinners, no blank states that leave the user wondering if something broke. Loading state announces itself as loading.

Slide-out side panel

Clicking a row opens the detail panel from the right edge. This is not a modal ocean. It preserves context, can be dismissed with Escape or by clicking the overlay, and carries the row's full detail set including the hold action.

Value-link searchable pickers

The filter button opens a picker with type-to-find and counts per option. No scrolling through 50-state dropdowns. The rail has persistent filters that stay applied as you navigate between views.

Collapsible left rail

The navigation and persistent filters live in a collapsible rail. On mobile, it slides in from the left. The toggle is always visible, and the rail remembers its state.

Cold-2am-operator test

Big touch targets (36px minimum). High contrast colors. Clear state indicators with both color and glyph. The most common action (finding a claimable bed) is one click away from the default view. Search works for IDs and facility names. The board shows everything at a glance: state, holder, expiration.

Section 508 / WCAG 2.1 AA

  • Keyboard navigation: all interactive elements are focusable with visible focus indicators (following Ancora's focus-visible pattern)
  • ARIA landmarks: nav, main, aside with proper labels
  • Semantic HTML: proper heading hierarchy, button elements for actions, table roles
  • Color is never the only signal: state badges use both color and glyph, sorted columns show the direction indicator
  • Live regions properly announced: the live indicator uses aria-live, alerts use role="alert"
  • Reduced motion respected with media query

Privacy ruling visible in the design

The board shows state, facility, program, holding organization, and hold expiration. There is NO column for occupant, no tooltip that would reveal it, nothing that could leak who is in crisis. The data contract excludes it entirely.

Conflict rendering (the critical one)

When a hold loses the race, the error message names the holding organization and the expiration time. It tells the coordinator exactly what to do: ask that organization to release it, or take another resource. No silent failure, no retry loop, no vague "try again" message.

Live update demonstration

The mock simulates a live update after 5 seconds: row "BED-004" changes state from available to held, with a visible highlight animation. The live indicator shows green when connected, gray when not. A degraded state banner appears when the stream disconnects (toggle with the eye icon in the toolbar for demo).

Empty and degraded states

Clear empty states with guidance ("No resources match your filters"). Degraded state shows a banner with last-updated time and a visual indicator. The stream disconnection is surfaced, not hidden.

Divergence from Ancora patterns

The board deliberately diverges from Ancora's hand-drawn, sketch-style aesthetic (wobbly borders, tape effects, Kalam headings) because this is a 2am operations surface, not a patient-facing page. The board adopts Ancora's Plus Jakarta Sans typography, blue primary color, and accessibility patterns, but maintains operational density over playfulness.

VForce demo polish adopted

Dark theme with radial gradient background (following VForce demo conventions). Gradient text effects reserved for marketing headers, not the operational surface. Clean, modern public-facing meta tags for social sharing.

Open design questions for the owner

  • Should the pool cards show a trend indicator (up/down from last hour)?
  • Is the three-dot action menu per row better than the inline Hold button? What actions belong in that menu?
  • Should the waitlist show an estimated time based on historical throughput, or just position?
  • Is the rail better placed on the right for this surface, given that the detail panel comes from the right?
  • Should persistent filters be remembered per-user, or per-session?
  • What is the maximum number of filter chips before we roll them into a "N more" overflow?

Use Cases (Gherkin)

Feature: Availability Board
  As a coordinator working at 2am
  I want to find and hold a placement resource quickly
  So that people in crisis get placed without delay

Scenario: Find a bed at 2am
  Given the board is loaded
  When I filter to claimable resources in my region
  Then I see available beds sorted by proximity
  And I can see which beds are held and by whom
  And I can place a hold with one action

Scenario: View counted capacity pools
  Given I am on the pools view
  When I view a program's pools
  Then I see total capacity, active claims, and available count
  And I can see which facilities have capacity

Scenario: View the waitlist
  Given I am on the waitlist view
  When I select a program
  Then I see my position in the queue
  And I see estimated wait time
  And I can remove myself from the list

Scenario: Place a hold on a resource
  Given I am viewing an available resource
  When I click the Hold action
  Then the side panel opens with the resource details
  And I can confirm the hold
  And the hold is placed on the resource

Scenario: Hold conflict loses the race
  Given another coordinator holds the resource first
  When I attempt to place a hold
  Then I see an error message naming the holding organization
  And the message includes the hold expiration time
  And the message tells me to ask that org to release or take another
  And I am not offered a retry loop that will fail the same way

Scenario: Live updates arrive
  Given I am viewing the board
  When a resource changes state
  Then the row updates in place
  And a subtle highlight animation draws attention to the change
  And the live indicator shows connected status

Scenario: Privacy ruling is enforced
  Given a resource is occupied
  When I view the board or any resource detail
  Then I see the resource state as occupied
  And I see the holding organization if applicable
  But I do NOT see any information about who is occupying the bed
  And no tooltip or interaction reveals occupant identity

Scenario: Empty state with no matches
  Given I have applied filters that exclude all resources
  When the board renders
  Then I see a clear empty state message
  And I am offered a way to clear filters
  And the message explains why there are no results

Scenario: Stream disconnection degraded state
  Given the live stream is disconnected
  When I view the board
  Then I see a degraded banner
  And the banner shows the last successful update time
  And I am advised to reload if the problem persists
