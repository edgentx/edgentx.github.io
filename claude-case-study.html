Case Study

Governed Claude in production at Edgent

Edgent LLC is a service-disabled veteran-owned small business in Bastrop, Texas, serving federal, state, and K-12 buyers. Claude is the production model behind our platform. This page describes four places it runs, the governance pattern shared by all of them, and the engineering workflow that builds them, with links to the live surfaces.

Where Claude runs

1. Natural-language analytics over a governed data lakehouse

VForce360 carries a natural-language analyst surface built on Claude. A user asks a question of a data product in plain English; Claude generates SQL that the platform executes under the user's own permissions, with the query visible, editable, and re-runnable in the conversation. Two mechanisms keep answers honest: every column carries a semantic contract (a role such as count, money, share, or date, plus grain and derivation) that Claude binds against, and an implausible result trips a self-check round before the user sees it. Follow-up questions inherit the prior round's tables and intent, so "what about the top 100" changes a limit, not the dataset.

  • Authorization is enforced by the platform, not the model: the SQL gate resolves every table reference and checks it against the user's relationship-based grants before execution.
  • A publicly readable instance of the same data platform serves a district transparency dashboard on synthetic data with privacy suppression applied in the pipeline.

Live: rcsd-demo.vforce360.ai/dashboard (public, synthetic data) and the analyst view.

2. Federal business development: analysis, scoring, and proposal generation

Edgent Cockpit ingests public procurement opportunities from federal and state sources into a corpus of more than 16,000 records. Claude analyzes each opportunity for fit against the firm's capability profile, a deterministic funnel scores it, and the two move together so a recommendation never sits over a stale score. For pursuits, Claude generates proposal documents structured from the buyer's own response form, with a checklist that reports what is complete and what still needs the owner. An hourly triage job reads the business mailbox, resolves amendments to their existing opportunities, and drafts a digest. Every outbound email Claude drafts lands as a draft for a human to send; the system has no send capability, and that constraint is enforced by a test that fails the build if one ever appears.

Live: cockpit.edgentllc.com (SSO; demonstration on request).

3. Instructional design and learning delivery

Edgent's instructional design practice produces curriculum through an AI-augmented pipeline on Claude, structured on the ADDIE method. Accessibility is a build gate, not a review step: every package is driven through a real browser and scanned for WCAG 2.1 AA conformance at load and after interaction before it can be imported, and a content linter checks house style, structure, code samples, and measurement hooks at authoring time. Learning records land as xAPI statements for measurement of practice change rather than completion alone.

Live: acme.lms.vforce360.ai (open demonstration shelf, no account needed).

4. Claude Code as the engineering system

The platform above is built with Claude Code. Engineering work runs as issue-first, plan-first lanes: a tracked issue exists before any agent is dispatched, acceptance criteria are written as Gherkin scenarios, implementation lands through pull requests that merge only on a fully green run of the complete check set, and deployment rides continuous integration, never a hand-applied change. A post-release verification job exercises every canonical product surface after each deploy and pages the team on any failure. Lessons learned are recorded to a shared engineering memory that every agent recalls before starting non-trivial work, so a problem solved once stays solved.

  • Multiple Claude Code agents work in parallel lanes across repositories, coordinating through issues and isolated worktrees.
  • The same discipline applies to content: courses, proposals, and email drafts are versioned, linted, and reviewed like code.

Delivery method: edgentllc.com/process. Public code examples: github.com/edgentx/code-examples.

The governance pattern, shared by all four

  • Human in the loop, enforced by the system. AI drafts; a person reviews and decides. The review gate is code, not policy.
  • Relationship-based access control. Every data read the model triggers is authorized against the requesting user's grants. The model never holds broader access than the person asking.
  • Tenant isolation. Each customer tenant runs on its own dedicated host with its own identity realm and data boundary.
  • Audit. AI-assisted actions are recorded in a hash-chained audit trail with the acting identity and, where an agent acts for a person, both identities.
  • Privacy by construction. Small-population suppression in the data pipeline, field-level encryption for sensitive payloads, and no customer data used for training.
  • Deployable inside the customer's boundary. Kubernetes, government and commercial clouds, or the customer's accredited environment.
